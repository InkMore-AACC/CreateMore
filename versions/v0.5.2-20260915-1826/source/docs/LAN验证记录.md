# 局域网协作实现与验证记录

日期：2026-09-07。以下区分当前实现、同机测试与未完成事项，不代表已经通过真实多台 Windows 电脑验收。

## 已实现的后端与主服务接入

- 默认不监听网络。用户点击发起共享或加入共享后才建立局域网端点；限定本机、私有局域网及链路本地地址，不修改防火墙、路由器或系统服务。
- `app/core/collaboration.cjs` 使用 Node 标准库；`await service.ready` 后即可取得持久身份。Ed25519 身份公私钥仅保存在本机身份文件，成员 ID 由公钥导出；成员颜色及会话成员表持久保存。
- 可选择无密码共享或密码共享。密码通过随机挑战证明，不明文传输。网络消息采用临时 X25519 密钥交换与 AES-256-GCM 加密，令牌也位于加密消息中；序列窗口拒绝重放。已见过的共享地址固定主机指纹，主机身份变化拒绝自动信任。
- 画布、成员及素材同步，不广播个人视野、缩放、设置或私人 Codex 对话。快照剥离凭据字段及本机绝对素材路径，素材通过固定 ID 关联。
- 所有卡片修改经过同一所有者校验：协调者不额外获得卡片编辑权；引用可以来自其他成员，输入连线修改权跟随目标卡片；分组只能包含自己的卡片。
- 一次画布操作使用原子批量发布。整批先验证，再保存；错误不发生“前几项成功、后几项失败”。版本冲突明确拒绝，幂等编号记录随会话持久保存，重试返回当前状态，不把客户端回退到旧快照。
- 素材按 256 KiB 分块传输，以 SHA-256 校验完整文件；中断后按已保存偏移续传。接收副本在数据目录与实际画布素材目录持久保存，删除卡片、离开或停止共享不删除文件。大于 64 MiB 的文件通过本地文件复制回调落盘，不要求整个视频同时放进内存。
- 首次加入共享时，在当前项目下创建独立本地画布；原私人画布及其素材不自动共享。重新连接已经加入的会话继续使用原绑定画布。
- 主服务将共享回调绑定到具体画布对象。活动共享期间禁止切换到其他画布；停止或离开后，迟到回调也不误写新画布。远端素材清单不会覆盖已建立的本机素材路径。
- 改密码使当前验证令牌失效，成员必须用当前密码重新加入。主动停止共享发布持久结束记录；成员已有素材不撤回。私人任务与生成凭据不因停止共享被取消或广播。

## 接管与写入安全策略

当前采用保守的多数确认方案，不以简单“主机心跳失败”宣称已经解决双主。

1. 正常共享修改先取得当前成员表多数的持久确认；成员加入／离开同时满足旧、新成员表多数。
2. 接管为手动操作，要求原协调者不可达、候选成员具有完整素材、相同画布版本，并获得当前成员多数签名。
3. 每个成员对一个新协调周期只持久确认一位候选者；旧周期写入会被隔离。协调者失去多数后不能继续成功写入。
4. 若发生“已经收到写入、尚未确认提交”的中断，保留待确认记录并阻止后续覆盖；使用 `recoverPending()` 重连确认。不会自动抛弃可能已经提交的结果。

明确的保守限制：

- 三位成员中两位仍在线，已通过接管后继续编辑测试。
- 只有两位成员时，一位突然断电，剩下一位不能形成多数，因此不会直接接管；本地完整副本仍保留。无中心仲裁下不能同时无条件保证两机断线接管与分区双主安全。需要产品确定“明确另存独立分支”还是添加见证成员的后续体验；目前不做危险的强制接管。
- 存在未确认写入时，接管会被保守阻止；尚未实现自动恢复所有极端竞态。
- 失败的接管投票承诺不会被静默撤销。需恢复多数成员协调，或另存独立画布；不能仅因为旧主重新上线就自动丢弃承诺。
- 主动停止需要会话多数确认；网络分区中无法确认所有成员已知停止时，不显示虚假的全体停止成功。
- 当前是应用层的协调复制实现，不是已由专业安全审计或形式化验证过的通用分布式数据库。

## 调用契约

`CollaborationService({dataDir,getSnapshot,applySnapshot,listAssets,readAsset,writeAsset,onEvent})` 提供：

- `startHosting({port,password,canvasId,host?})`、`join({url,password,port?,host?,expectedHostId?})`。
- `status()`、`syncNow()`、`leave()`、`stopSharing()`、`changePassword(password)`、`takeover({password?})`、`recoverPending()`、`dispose()`。
- `publish({type,node?,id?,patch?,edge?,group?,baseRevision?,idempotencyKey?})`；类型包括 `node.create`、`node.update`、`node.delete`、`edge.create`、`edge.delete`、`group.upsert`、`group.delete`，以及 `{type:'batch',operations:[...]}`。
- `addAsset(meta,Buffer或本地绝对路径)`；素材清单为 `{id,name,type,size,sha256,owner}`。
- `readAsset(id)` 返回 Buffer 或本地绝对路径；`writeAsset(meta,buffer,{sourcePath})` 收到已验证素材，较大素材的 buffer 为 null，使用 sourcePath 复制。

业务主服务的 `syncSharedAssets(canvasSession)` 在导入／产物／Agent 修改入口调用，先保存目标状态，再同步素材并原子广播结构；它跳过未共享或非绑定画布，断线时明确报错且保留本地素材。

## ComfyUI 执行资源共享网关

新增 `app/core/shared-execution.cjs`，复用同一个身份与加密网络通道，但不复用他人卡片修改权限。

- 资源主人显式开放某个本机绑定的 ComfyUI 工作流，可限制允许成员、生成类型、输入素材类型和数量以及公开参数范围。默认没有开放资源；应用重启后不会自动重新开放。
- 远端不能提交任意工作流 JSON、设备路径、输出目录、URL、脚本或凭据。工作流及执行配置由资源设备本地解析，发起者只发送提示词、公开参数和已共享素材 ID。
- 实际任务进入资源设备现有 `TaskQueue`，保持同一 ComfyUI 实例串行；发起者只可查询与取消自己发起的任务。资源主人另有显式设备级取消、暂停后续调度入口，不因此获得他人卡片编辑权。
- 停止开放阻止新任务，不暗中取消已提交任务。网络共享停止后，已建立的验证通道仍可取回既有任务结果；设备退出后不声称计算迁移成功。
- 网络状态返回真实任务状态、可取得进度、错误和输出清单，不返回设备磁盘路径或连接配置。结果限定在本次任务输出目录，通过分块传输、续传与哈希校验保存到发起者目录，随后才能进入普通素材与卡片关联流程。
- 幂等请求避免重复排队；提交结果不明确时保留未知记录，不自动重新生成。

首阶段的 24 项 LAN 相关测试通过，其中网关 7 项、业务装配 3 项使用真实队列、加密网络与磁盘文件，生成来源使用测试替身。覆盖非协调者设备执行、输入同步、结果下载校验、任务权限、能力与路径限制、具名端口、串行调度、确认取消、停止开放以及共享停止后的已有结果取回。业务装配还验证产物回到发起者自己的卡片、接收设备不误改当前卡片、按真实任务编号恢复而不重新生成，以及提交关联重启后仍保留。**这不等于已经通过真实 ComfyUI 模型生成或真实多机测试。**

构造器：`SharedExecutionGateway({dataDir,collaboration,describeProvider,resolveWorkflow,submitTask,getTask,cancelTask,pauseResource?,onEvent?})`，初始化等待 `gateway.ready`。

- `describeProvider('comfyui')` 返回 `{available,kinds,inputTypes,parameters,workflows:[{id,name,kinds}]}`，工作流必须是设备侧已绑定的稳定 ID。
- `resolveWorkflow(workflowId,kind)` 只在设备本机返回实际工作流配置。
- `submitTask(snapshot,requesterId)` 进入已有任务队列；snapshot 标记 `remoteExecution:true`，设备侧不得把结果写入自己当前画布卡片。
- `getTask(taskId)` 返回含真实 result 的任务；`cancelTask(taskId,requesterId)` 复用队列权限；`pauseResource(resourceId,paused)` 仅暂停后续调度。
- `offer({provider:'comfyui',workflowId,kind,enabled:true,allowedMembers?})`、`stopOffer(offerId)` 与 `listOffers()` 管理可发现能力。
- `submitRemote({deviceId,offerId,kind,prompt,parameters,references:[{assetId,inputId?}],requestId?,requestCanvasId?})` 返回 `{deviceId,jobId,taskId,state}`。`inputId` 仅接受 1–80 位固定英文数字标识；与资源主人公开端口和当前实际工作流再次核对，未知端口、重复单输入、缺少必需输入均拒绝，不按显示名称猜测。
- `remoteStatus({deviceId,jobId})` 返回状态及无路径输出清单；`cancelRemote(...)` 只控制发起者本人的任务。
- `downloadResults({deviceId,jobId,outputDir})` 返回 `{text,outputs:[{path,type,size,sha256}],remote:{deviceId,jobId,taskId}}`，仅这里的 path 是发起者本机已保存文件。

主服务装配文件为 `app/core/execution-actions.cjs`。`install(service)` 连接当前真实 ProviderHub、固定默认工作流映射与 TaskQueue；`submitNode` 创建来源为 `shared-comfyui` 的发起端可追踪任务；`run/reconcile/cancel` 处理真实设备编号、状态与结果回传。工作流、模型与凭据仍留在设备本机。公开默认参数在提交前固定；没有映射的 UI 参数不被冒充成设备能力。

## 账号与 API 执行资源扩展

当前可显式开放已配置的 Codex 纯文字、Image2 图片、Ollama、OpenAI-compatible 文字，以及本机有效映射配合主人固定云端编号的 RunningHub。成员不能选择新的端点、模型、账号、线程、工具、Skill、文件路径或工作流；只使用主人公布的输出类型、素材类型与公开参数。

账号类来源必须由主人另行勾选 `allowAccountUsage`，默认不勾选。此授权允许指定成员消耗主人的额度／费用，不含费用上限与分账。配置、模型、凭据、映射或 Codex 账号变化使旧资源绑定失效，需要重新开放；Codex／Image2 在真正发回合前再次核对冻结账号指纹。重启不自动重开资源。私人聊天和画布操作工具不向远端开放。

设备任务进入各自真实来源的同一队列。设备暂停按所选来源生效，界面不会把“暂停 Image2”说成暂停 ComfyUI。失败或取消前已完成的真实文件按原输出目录、分块和哈希校验回传；无输出的失败不当成功。发起者可核对自己的原 job；同步文字 API 若没有查询能力则保留未知，不自动再提交。

新增来源与局部结果的定向测试使用真实 TaskQueue、加密环回网络和磁盘文件，生成提供方是测试替身；本批 18 项通过，6 项来源测试包含账号指纹、额度确认与配置变化拒绝。没有进行真实付费 API 或 Codex 共享计费调用，不把此证据混同于前面实际 ComfyUI 共享生图。同步 API 不能保证服务器停止计费；RunningHub 只有查询确认取消后才标为已取消，收到取消请求本身不是终态。真实跨电脑与系统故障仍待环境验收。

## 最后审查修订：输入版本与素材归属

共享任务提交时固定每份素材的 SHA-256、字节数和端口标识。发起端和设备端各自复制独立输入后校验；等待期间共享素材版本改变会明确拒绝，不把新版本静默用于旧任务。没有实现自动传输历史版本，用户需重新确认当前素材后新建任务。

上传开始时的归属检查之外，最终串行提交前再次核对当前所有者。两个成员先后开始相同 ID 的上传，先提交者取得归属后，另一位成员不能覆盖其文件或引用。
