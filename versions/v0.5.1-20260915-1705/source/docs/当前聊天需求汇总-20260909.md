- 已有正式软件，`app/` 是源码，`dist/` 是打包输出，`prototype/main-canvas.html` 是历史草图。不能再按“尚未正式编码”理解项目。
- 画布的设计、交互、卡片内部排版、工具及按钮尽可能完整参考 LibTV。现有架构可以调整，不拘泥于旧草图；保留项目自有的本地生成等能力，不复刻商业推广页面。
- 当前优先完善画布交互，随后提出并落实设置页方案。不得用局部测试代替所有功能可用的结论。
- 本轮仅整理文档，不修改软件、配置、工程，不执行生成、打包或发布。

## 2. 卡片体系

| 卡片 | 选中后的界面 |
|---|---|
| 普通图片、普通视频、普通文本、普通声音 | 只有相应顶部工具栏，没有下方生成框 |
| 生成图片、生成视频、生成文本、生成声音 | 顶部工具栏与同类型普通卡片一致，另有下方生成框 |
| 生成脚本 | 专属生成及脚本编辑交互，细节对照 LibTV |
| 自定义卡片 | 按工作流及映射定义输入输出和公开参数 |
| 风格卡片 | 风格 Skill 输入，连接到目标生成卡片 |

- 没有角色卡片。角色属于类似预设的资源体系，更具体的区别由用户后续补充，不阻塞画布改造。
- 上传到画布或从资产栏拖入的图片，无论来自本机还是生成结果，都是普通图片素材卡片。其他媒体按相同素材／生成身份区分。
- 所有图片和视频类卡片按实际媒体比例自适应，不固定横图并裁掉内容。
- 其他卡片的按钮不能机械套用图片卡片；逐类实地观察 LibTV。

## 3. 生成图片框

### 3.1 从上到下的固定布局

1. 第一排左侧依次为添加参考、标记、风格、聚焦，最右侧为扩大编辑框。
2. 输入素材栏，有输入时才显示，包含参考图片、连接文本和风格 Skill。
3. 提示词输入栏，为框内最大区域，支持 `@` 图片引用。
4. 最下一排左侧依次为生成来源、比例／像素／数量，最右侧为生成按钮。

### 3.2 添加参考与素材栏

- 点击添加参考后，整个画布变暗，仅普通图片和生成图片卡片亮起；点选后加入当前卡片的参考输入并创建连线。
- 文本卡片只能通过连线成为输入，不能通过图片参考选择器添加。
- 悬停素材出现临时图片／文本预览，移开消失。
- 按住图片素材拖动可改变输入顺序；实际提交的参考顺序必须同步。
- 悬停每项素材时右上角出现叉号，点击同时移除输入和对应连线。
- 输入 `@` 弹出选择框，只列出已添加的图片参考，不列全部画布图片或将文本当成图片引用。

### 3.3 标记

- 鼠标变为标记图标，除当前生成图片卡片外的卡片变暗。
- 点击图中物体，通过多模态模型识别是什么；图片上保留图钉、物体名称和大致范围虚线框，并把稳定的图钉链接加入提示词，方便修改描述。
- 不是普通涂画弹窗，也不是直接提交整图修改。
- 与其他生成功能一样，可配置 Codex、API、ComfyUI 工作流；实际来源必须具备图片理解能力。

### 3.4 风格

- 打开全软件共用的风格 Skill 库。
- 选择后创建风格 Skill 卡片，并作为输入连接到当前生成图片卡片。

### 3.5 聚焦

- 最新要求确认沿用当前聚焦裁切弹窗；弹窗中的图片按自身比例最大化显示并贴合图片框边缘。
- 在当前生成图片卡片的图片上框选区域；新卡片固定采用此次框选得到的自定义比例，不能再被标准比例静默覆盖。
- 裁切选区并高清放大到至少 1M 像素。
- 原卡片右侧出现新的生成图片卡片，原卡片作为输入并连线；保留原图，不能覆盖原卡片。
- 1K／2K／3K／4K 与宽、高、比例、像素量自动换算并保持框选比例；规格界面显示实际换算尺寸。
- 验证坐标、真实放大输出和结果回到新卡片，不能只创建空卡片就认定完成。
- 自动提交还是其他队列触发细节应对照 LibTV；不要把尚未验证的额外手动步骤写成用户要求。

### 3.6 来源与本地自动路由

- 图片来源只有三项：Codex Image2、API、ComfyUI 本地。
- 选本地后不再选择具体工作流。用户可在设置中存放多个备选，并更换生效绑定。
- 根据输入自动选择该功能绑定的文生图、单图参考／图生图、多图参考工作流。
- 工具工作流不得混入图片生成，也不得被旧卡片绑定或隐藏的内嵌工作流绕过隔离。
- 输入不支持时明确说明，不能静默丢参考图、偷换流程或忽略提示词。

### 3.7 规格与多结果

- 规格面板第一行：1:1、9:16、16:9、3:4、4:3、3:2、2:3、21:9，及自定义宽、高输入。
- 第二行：1K、2K、3K、4K；第三行：1 张、2 张、4 张。
- 点击生成进入队列。
- 多张结果在同一生成卡片堆叠，右上角展开；展开后每张右上角可设为主图。选择后成为本次主结果，并收起为一张生成图片卡片。

## 4. 全局交互

- 靠近连接点一定范围即可拉线；拖到兼容目标卡片范围即可连接，不要求精确命中小点。
- 新建卡片在鼠标位置，不移动视口、不擅自自动避让或整理。
- 工具栏与生成框固定相对卡片的位置，可超出视口；不能超界后换边、移动镜头或夹紧到屏幕内。
- 选中卡片时顶部工具全部展开，不制作两份工具栏，也不收进“更多”。由用户自行缩放、平移操作超界内容。
- 各类卡片、按钮、菜单、拖动和状态要真实鼠标键盘观察，未观察的不能声称已完整复刻。

## 5. 设置与 ComfyUI 原生映射

- 每一种生成卡片和每一个生成工具独立配置，不只按图片／视频／声音／文本四大类混放。
- 每种功能具有 Codex、API、ComfyUI 三种方式的配置结构；能力不足时明确说明，不能伪装可用。
- 设置全软件共用。需清楚层级、返回与关闭，不仅有关闭按钮；画布交互完善后给出设置方案。
- 早期“工作流与映射始终可见”被最新普通卡片自动路由要求部分替代：普通生成卡片不再选择具体流程；自定义卡片及工作流配置处入口仍需清楚可见。
- 编辑映射必须显示对应工作流的真实 ComfyUI 画布，可选每个节点及其参数，设为输入、输出或公开参数，并显示在画布卡片上。
- 不能只加一个“打开 ComfyUI”外链按钮，也不能打开空画布或报错后宣称完成。
- 参考的是 DX OS，不是 EX OS；只参考方式，不照搬其 Bug。

## 6. 本地工作流与运行环境

- 每个生成功能都需要本地工作流。做不到或需巨大模型时记录原因供用户确认，不静默降级。
- 先扫描现有模型库，再研究社区高热度、效果好的开源工作流，学习并构建适配方案，优先利用现有模型。
- 重点来源为 Civitai、RunningHub 一类社区，GitHub 工作流也可作为来源和补充。
- 不未经对比就宣称“最优”；说明适用输入、依赖、效果、资源成本和实测范围。
- 已授权新增模型和第三方节点，累计空间预算 100 GB，必须使用现有 ComfyUI 目录体系；不另装一套、不擅自降级。
- TTS 优先已有本地模型，研究支持生成、音色克隆及情绪变化的方案，不能用机械朗读替代。
- 连接配置需核对用户真正打开的 EXE 及配置路径；诊断程序读到正确值不代表正式窗口正常。
- 启动／复用后台必须有明确反馈。失败后区分仍在运算、排队、模型驻留显存，提供进程、任务、日志定位和安全停止方式。
- 不只把前台改成失败而不核对后台，也不擅自停止归属不明的任务；避免重复实例抢显存。
