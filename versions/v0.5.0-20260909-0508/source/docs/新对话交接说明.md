# CreateMore 新对话交接说明

## 任务目标

继续设计并逐步实现 Windows 本地画布软件 CreateMore。产品参考 LibTV 的画布功能、节点、卡片工具与交互，但软件整体导航、技术架构和本地生成能力按本项目已确认方案设计。

## 开始工作前必须读取

1. `docs/已确认需求与遗漏核对.md`：当前唯一有效的需求与架构基线。以标记为“已确认”的内容为准；不要让旧聊天提案覆盖最新决定。
2. `prototype/main-canvas.html`：第一版可交互草图。它是设计核对稿，不是正式产品代码。

## 当前草图已经落实

- 生成任务窗口将本地 ComfyUI 与外部生成排成左右两列。
- 普通浮动窗口点击画布空白处关闭，同时保留关闭按钮。
- 卡片默认没有常驻灰色外边框；选中后显示 2 像素细描边。
- 图片生成节点未选中时为简洁灰色卡片；选中后才展开参数编辑区域。
- 草图中的生成、复制、映射等操作均为交互示意，没有连接真实服务。

## 新对话的第一项工作

先验证浏览器控制是否能正常读取 LibTV：

- 优先读取用户已经在 Edge 打开的 LibTV 画布标签页。
- 当前可见画布地址：`https://www.liblib.tv/canvas?spaceId=7653453&projectId=5224f4886deb4d248816f00e92f609e3`
- 另一个包含较多节点的参考画布：`https://www.liblib.tv/canvas?projectId=45c86f78b71d42919588f25ca9a66075&spaceId=7679254`
- 用户此前明确允许在其提供的测试画布中创建、编辑测试节点并保留，也允许使用测试积分；第一次连接先只读观察，确有必要时再操作。

重点核对卡片未选中、选中、参数展开、顶部工具栏、节点内容排版、弹窗关闭和连线视觉。把观察结果与 `prototype/main-canvas.html` 对照，只修改有明确依据的部分。

## 浏览器故障背景

原对话中的浏览器控制会话可以列出 Edge 标签页，但读取任何页面都会超时；Bing 与 `example.com` 也失败，因此不是 LibTV 防控。用户在另一个对话中已经成功读取 LibTV，说明更可能是原对话的浏览器会话异常。新对话先重新验证，不继承“LibTV 无法访问”的结论。

## 工作边界

- 当前仍处于需求核对与草图阶段，尚未开始正式软件编码。
- 不复刻 LibTV 官网、会员、积分或推广页面。
- 不运行、修改或删除 `chat-image-probe/`；该目录是已放弃方案的独立实验文件。
- 任何实现状态都应区分：已写代码、结构检查通过、连接成功、真实输出成功。
